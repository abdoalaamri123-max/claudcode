# Chapter 10: Networks and Trees
*Source: Holmes & Huber, Modern Statistics for Modern Biology, https://www.huber.embl.de/msmb/10-chap.html*

## Core concepts

- A graph is `(V,E)`: vertices + edges. Undirected graphs have symmetric adjacency matrix (`M = M^T`); directed graphs do not. Edge list ("from-to" table) and adjacency matrix are equivalent encodings.
- **Graph layout is not statistically meaningful by itself.** "Graphs do not live in physical space (neither 2D nor 3D) but are literally just sets of nodes and edges." Any given graph has many valid 2D/3D layouts (Fruchterman-Reingold, MDS-style, circular, etc.); node proximity in a plotted layout is an artifact of the layout algorithm unless edges carry an explicit length/weight attribute that itself encodes a meaningful distance.
- Sparse graph: `#E ~ O(#V)` (edge list / sparse matrix storage is efficient). Dense graph: `#E ~ O(#V^2)` (adjacency matrix memory becomes an issue). Example: ~2500 nodes, ~20000 edges → full adjacency matrix needs >6M cells (mostly zero) vs. 20000 for the edge list.
- Bipartite graphs: two node types, edges only across types (e.g., taxa × sites, TF × regulatory region). Do not add edges within a type.
- Directed graph + edge weights = network; Markov chains are directed weighted graphs on states, with transition-probability edges. A state with only incoming edges + a self-edge is an absorbing state.
- Node degree, centrality, betweenness summarize structural importance but are purely descriptive; they only become inferential once compared against a **null model** (e.g., a random/degree-preserving rewired graph), which this chapter does not build for centrality — treat any claim like "this hub is significant" with the same skepticism as an untested layout.
- Gene Ontology (GO) and similar pathway databases are directed acyclic graphs (DAGs): edges run from specific (child) to general (parent) terms, so gene sets at different GO nodes routinely **overlap** (a gene inherits membership in all its ancestors' terms).
- Enrichment / overrepresentation testing = **Fisher's exact test** / **hypergeometric test**: candidates classified into categories, and asking whether a category is over/under-represented in the "significant" subset relative to the full universe. Both are exact/nonparametric — "exact" refers to exhaustive enumeration, not to certainty of the conclusion.
- Hypergeometric expectation: universe size `N`, `k` = category size within the universe, draw size `m` (the "significant" set) → expected count in category = `k·m/N`. Compare the observed count in the category to this null.
- High-scoring subnetwork / hotspot search (BioNet-style): score each node from a t-statistic or -log(p) (so small p → large score, and taking absolute value or a two-sided score handles genes that are both up- and down-regulated within a pathway), fit a Beta-Uniform Mixture (BUM) to the p-values (`f(x|a,π0) = π0 + (1-π0)·a·x^(a-1)`, `0<x≤1`, `0<a<1`), then search the fixed "skeleton" network for the maximal-scoring connected subgraph. Finding the exact maximal subgraph is **NP-hard**; real pipelines use heuristics (simulated annealing, seed-and-grow, MST-based search) — the result is a heuristic optimum, not a guaranteed global one.
- Phylogenetic trees are rooted, (usually) binary, acyclic graphs; only leaves (OTUs, "operational taxonomic units") are observed/contemporary, internal nodes are ancestral and inferred, not measured.
- Evolutionary substitution models are continuous-time Markov chains assumed **time-homogeneous** (constant rate over history = the "molecular clock" hypothesis). Nested model family: Jukes-Cantor (JC69, 1 rate parameter, all substitutions equally likely) ⊂ Kimura (K80, 2 parameters: one rate for transitions [purine↔purine or pyrimidine↔pyrimidine], one for transversions) ⊂ GTR (General Time Reversible, 6 free parameters, most flexible).
- Tree estimation approaches: parsimony (nonparametric; minimizes total changes; equivalent to the Steiner-tree problem), maximum likelihood (parametric; needs a substitution model), Bayesian/MCMC (e.g., MrBayes, BEAST; gives a posterior distribution over trees), and neighbor-joining/UPGMA (semi-parametric; hierarchical-clustering-like algorithm but distances are computed from a parametric evolutionary model first).
- Hierarchical multiple testing (Benjamini-Yekutieli 2003 / Benjamini-Bogomolov 2014): test a taxon/node only if its parent (higher taxonomic level) was already found significant; controls FDR variants while exploiting the tree structure, gaining power when true signal clusters phylogenetically (e.g., a whole genus responds, not one isolated species).
- Minimum spanning tree (MST): the spanning tree of minimum total edge length for a set of vertices with pairwise distances; used both as a compact "skeleton" for hotspot search and as the basis of a two-sample test.
- **Friedman-Rafsky test**: generalizes the univariate Wald-Wolfowitz runs test to multivariate/graph data. Build an MST (or k-NN graph, or a distance-threshold graph) over samples, color vertices by a categorical covariate, count "pure" edges `S` (both endpoints same label); compare `S` to a null built by permuting vertex labels many times. Small `S` (few same-label edges) relative to permutation null ⇒ groups are spatially/graph-segregated ⇒ reject "same distribution."
- Choice of skeleton graph (MST vs. k-NN vs. distance threshold) is a modeling decision, not dictated by the data — different choices can give different sensitivity/power; check robustness across at least MST and k-NN.
- For sparse presence/absence data (e.g., microbiome), prefer Jaccard-based co-occurrence graphs over Pearson-correlation networks — correlation is appropriate for other settings but misleading for sparse compositional data.

## Common mistakes / pitfalls

- **Wrong background/universe set** for an enrichment test: the universe `N` must be the actual set of candidate genes/features that *could* have been called significant (e.g., all genes tested/detected in the assay), not the whole genome or an arbitrary annotated set. Using the wrong universe changes the hypergeometric null entirely and can flip enrichment conclusions.
- **Equal raw counts ≠ equal enrichment.** Worked example: universe of N=1000 genes (500 yellow, 100 blue, 400 red); significant set of m=75 has 25 of each color. Despite identical raw counts, blue (only 100/1000 of the universe) is strongly enriched while yellow and red are not — always normalize by each category's size in the universe, never eyeball raw counts.
- **Not enough permutations / Monte Carlo draws.** The book's own null-calibration example used 20,000 resamples to show the observed count (25) never occurred in the null; too few permutations (a) under-resolves small p-values (the smallest attainable p-value is roughly `1/(nperm+1)` — e.g., `nperm=1000` cannot report p below ~0.001, and the chapter's own MST example reports `p = 0.000999`, i.e., it hit that floor) and (b) gives a noisy/coarse null histogram. Always report nperm and check the observed statistic isn't sitting at the resolution limit.
- **Permuting the wrong axis / breaking nested structure.** In the Friedman-Rafsky mice/litter example, naively permuting all vertex labels (ignoring that samples are nested in mice, and mice in litters) would destroy the very correlation structure being tested and inflate false positives. The correct approach permutes only the nested factor's labels *within* the grouping variable (e.g., permute litter labels within each mouse) — implemented via a `grouping` argument. Any permutation test on clustered/repeated-measures/phylogenetically related data must respect that nesting or blocking in the permutation scheme, not just in the naive label shuffle.
- **Treating overlapping/redundant gene sets as independent tests.** Because GO terms form a DAG, a "significant" child term and its ancestor terms are testing highly overlapping (not independent) gene memberships; running many overlapping category tests and correcting only as if they were independent overstates power and undercounts effectively-correlated tests. The chapter's answer is hierarchical testing (test parent first, descend only if significant) rather than flat independent per-category testing.
- **Not correcting for multiple pathway/category tests at all.** Enrichment is virtually always run across many categories (GO terms, pathways) simultaneously; each one is a hypothesis test and needs joint FDR control (as in Ch. 6), not raw per-category p-values.
- **Phylogenetic / hierarchical non-independence treated as i.i.d.** Individual taxa/species/OTUs sharing recent common ancestry are not independent samples: if one Ruminococcus species associates with age for a genus-level biological reason, related species will show correlated (not independent) signals. Naive per-taxon testing + flat FDR ignores this and either misses power or misattributes significance to the wrong level; use tree-aware/hierarchical testing instead.
- **Treating a graph layout, node distance, or network picture as if it encoded a tested statistical distance** without an accompanying null model (permutation test, random graph comparison) — e.g., pointing at clique-like clusters or hub nodes in a plotted network as "significant" per se. Only edge attributes with explicit, meaningful lengths carry distance information; a nice-looking layout does not.
- **Naive (Hamming) distance underestimates evolutionary distance**, especially for larger true divergence: multiple substitutions at the same site overwrite earlier ones ("multiple hits"/saturation), so raw mismatch counts undercount actual mutational events; the underestimation bias grows with true distance. Use a model-based correction (JC69/K80/GTR distance) rather than a raw Hamming/percent-identity distance for tree building.
- **Ignoring the molecular clock assumption.** Standard tree-estimation models assume a constant substitution rate across lineages (time-homogeneity). If rates vary strongly across branches and this isn't modeled, branch lengths/tree topology become non-identifiable — you cannot distinguish among multiple mutational histories that fit the data equally well.
- **Too-high assumed/simulated mutation rate saturates the signal** — with very high mutation rates, later substitutions overwrite earlier ones and the tree becomes harder, not easier, to recover from sequence data; there is a "sweet spot," not a monotonic relationship between mutation rate and inferential power.
- **Reporting a heuristic max-scoring subgraph as if it were exact.** Because the underlying combinatorial problem is NP-hard, module-detection results (BioNet, GXNA, etc.) depend on the search heuristic and initialization; results can vary in size/interpretability and should not be presented as a unique, globally optimal answer.
- **Building correlation networks on sparse/compositional data** (e.g., microbiome counts, presence/absence): spurious correlations are common; prefer Jaccard/co-occurrence-based graphs for this data type.

## Assumptions to verify

- Enrichment test: sampling is without replacement from one *correctly specified, fixed* universe; categories are mutually exclusive (or overlap is explicitly handled); the "significant" draw size and category sizes are all counted from the same universe.
- Permutation test: the units being permuted are exchangeable under the null; if samples are nested/blocked/related (litters, batches, phylogeny, repeated measures), the permutation scheme must preserve that structure (permute within blocks), not shuffle everything.
- Phylogenetic/evolutionary model: time-homogeneity (molecular clock) — check whether branch rates are plausibly constant, or whether a relaxed-clock/rate-variation model is needed.
- Any p-value-derived node scores (BUM model, mixture model): check the mixture model actually fits the p-value distribution (e.g., via QQ-plot) before trusting downstream node scores or module search.
- Any conclusion drawn from a network's visual layout, clique structure, or hub node: verify there is an underlying edge-length/weight semantics, or a null-model comparison, backing the interpretation.
- MST/Friedman-Rafsky test: distance metric used to build the skeleton graph is appropriate for the data type (e.g., Jaccard for sparse presence/absence, not Euclidean/Pearson).

## Diagnostic checks

- For enrichment results: recompute using the correct universe and re-derive expected counts (`k·m/N`) per category before trusting any "enriched" claim; spot check with a direct Monte Carlo resample of the exact urn model when in doubt (should match the analytic hypergeometric/Fisher p-value).
- For any permutation test: report `nperm`; confirm the observed statistic is not sitting at the `1/(nperm+1)` resolution floor; inspect the permutation null histogram (not just the p-value) for sanity (is it centered where theory predicts? is the observed value a clear outlier or borderline?).
- For nested-covariate tests: confirm the permutation routine has a grouping/blocking argument in use and that it is actually being passed the correct nesting variable (e.g., re-derive the naive vs. nested-permutation p-value and expect them to differ if nesting matters).
- For BUM / mixture-model node scoring: check the QQ-plot / histogram of the fitted mixture against the observed p-values before using derived scores for subgraph search.
- For tree estimation: compare distance-based (NJ/UPGMA) vs. ML tree likelihoods/topologies; check bootstrap support (parametric or nonparametric) on key branches rather than presenting a single point-estimate tree as certain.
- For skeleton-graph choice (MST vs. k-NN vs. threshold graph): re-run the Friedman-Rafsky-style test under at least two graph constructions and check the conclusion is robust, not an artifact of one particular skeleton.
- For hierarchical/tree-aware testing: verify which nodes were legitimately *not tested* (parent not significant, so children skipped for power) versus silently dropped from the report — these are not the same as "not significant."

## Quick checklist

- [ ] Enrichment universe `N` = actual candidate/tested set, not the whole genome or an arbitrary larger set.
- [ ] Category counts and "significant" counts both drawn from the same universe; expected counts computed as `k·m/N`, not eyeballed from raw counts.
- [ ] Multiple pathways/gene sets tested → FDR/multiple-testing correction applied across all of them.
- [ ] Overlapping gene sets (DAG-structured, e.g., GO) not treated as independent tests; consider hierarchical testing.
- [ ] Permutation test: enough permutations that the reported p-value isn't sitting at the `1/(nperm+1)` floor.
- [ ] Permutation test: permuted units respect any nesting/blocking/phylogenetic structure (grouping argument or block-permutation), not a flat global shuffle.
- [ ] Network layout, node clustering, hub/centrality claims are backed by a null model or explicit edge-length semantics, not read off a picture.
- [ ] Related samples/species/taxa (phylogenetically or hierarchically linked) are not tested as if i.i.d.; consider hierarchical/tree-aware multiple testing.
- [ ] Evolutionary distances computed from a substitution model (JC69/K80/GTR), not raw Hamming/percent-identity, especially for divergent sequences.
- [ ] Molecular-clock / time-homogeneity assumption checked or explicitly relaxed when comparing lineages with plausibly different rates.
- [ ] Max-scoring subgraph / module-detection results reported as heuristic, with sensitivity to search method noted, not as a unique global optimum.
- [ ] Sparse/compositional co-occurrence networks (e.g., microbiome) built with Jaccard-type distances, not Pearson correlation.
- [ ] Skeleton-graph choice (MST/k-NN/threshold) checked for robustness, not used as a single unexamined default.
