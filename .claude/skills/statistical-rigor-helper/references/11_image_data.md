# Chapter 11: Image Data
*Source: Holmes & Huber, Modern Statistics for Modern Biology, https://www.huber.embl.de/msmb/11-chap.html*

## Core concepts
- An image is an array of pixel intensities; check dynamic range (min/max) before any processing — e.g. a 16-bit scanner may only populate its lower 11-12 bits, so raw values cluster near 0 and need explicit rescaling before thresholding/comparison. Don't assume intensity is calibrated to a physical unit (fluorophore concentration, radiance) unless the pipeline actually calibrated it — pixel-to-metric spatial scale (pixels→µm) is more commonly, and more importantly, calibrated.
- Noise reduction by smoothing/linear filtering (convolution, Eq. `f*(x,y) = (1/N)ΣΣ f(x+s,y+t)`, or weighted via a kernel `w`) precedes segmentation. Gaussian/mean smoothing is linear: `w*(c1 f1 + c2 f2) = c1 w*f1 + c2 w*f2`. Python: `scipy.ndimage.gaussian_filter`/`uniform_filter`, `skimage.filters.gaussian`.
- Thresholding: **global** (single cutoff for whole image, e.g. `img > 0.5`, or Otsu) vs **adaptive/local** (cutoff varies per region, computed from a local background estimate). Adaptive thresholding = subtract a locally-smoothed background image (window larger than the objects, smaller than the illumination-gradient length scale) then threshold the residual, e.g. `(img - local_background) > offset`. Assumes objects are sparse enough that each local window is background-dominated. Python: `skimage.filters.threshold_local`, `cv2.adaptiveThreshold`; global: `skimage.filters.threshold_otsu`.
- Alternative to a single ad hoc cutoff: fit a **mixture model** to the (log) pixel-intensity histogram — e.g. log-normal background + flat/non-overlapping foreground — and set threshold = background mode + k·(robust width), or better, use posterior class-probability per pixel (cf. ilastik-style pixel classifiers) instead of a hard rule.
- Morphological operations clean up a binary mask: **erode** (shrink foreground, kills small specks/thin bridges), **dilate** (grow foreground), **open** = erode then dilate (removes small foreground noise, smooths boundaries without much size change), **fillHull**/binary-fill-holes (fills enclosed background holes). Python: `scipy.ndimage.binary_erosion/binary_dilation/binary_opening/binary_fill_holes`, `skimage.morphology`.
- **Connected-component labeling** turns a binary mask into per-object integer labels (Python: `scipy.ndimage.label`, `skimage.measure.label`). This is the transition from pixel-level to object-level data — every downstream "cell" statistic depends on this step being correct.
- **Voronoi tessellation / seeded region growing** (`propagate`-style algorithms) assigns each ambiguous pixel to its nearest seed object, used to (a) split touching objects and (b) grow a nuclear seed into a full cell-body segmentation constrained by a looser mask, trading off shape compactness vs. following the intensity signal (a `lambda`/weight parameter controls this trade-off). Python nearest analogue: `skimage.segmentation.watershed` (with markers + mask, no gradient image needed for pure Voronoi behavior), `scipy.spatial.Voronoi`.
- **Feature extraction**: once objects are segmented, compute per-object descriptors — intensity (mean/total per channel), shape (area, eccentricity, major axis), texture — one row per object, many columns per feature type/channel/mask combination. Python: `skimage.measure.regionprops`/`regionprops_table`. These object-level feature tables are the actual input to downstream clustering/classification/differential analysis — not raw pixel arrays.
- Different segmentation masks per channel are common and valid (e.g. nuclear mask for DAPI features, cell-body mask for actin/tubulin features) — always record which mask produced which feature.
- **Spatial point process** framework: cell centroids + type labels = a *marked point process* (table of x, y, class). The **homogeneous Poisson process** is the standard null model: constant intensity λ, independent counts in non-overlapping regions, count in area A ~ Poisson(λA). Used as the reference against which clustering/repulsion is judged.
- First-order statistic: **intensity** λ(p) = local expected point density, estimated by kernel density estimation with an **edge-correction factor** `e(p)` (points near the window boundary would otherwise be systematically undercounted). Python: `scipy.stats.gaussian_kde` (no built-in edge correction), or purpose-built spatial-stats packages (`pointpats`/PySAL, `squidpy.gr.co_occurrence`/`squidpy.gr.ripley` for spatial transcriptomics).
- Second-order statistics measure spatial dependence beyond intensity: **G-function** (CDF of nearest-neighbor distance; theoretical Poisson `G(w)=1-exp(-λπw²)`), **Ripley's K-function** (`λK(r)` = expected number of additional points within distance r of a random point; inhomogeneous version normalizes by local intensities at both points), **L-function** (`L(r)=√(K(r)/π)`, variance-stabilized, theoretical Poisson value `L(r)=r` — the standard plot for spotting deviation), **pair correlation function** `g(r) = (1/2πr)·dK/dr` (g≡1 for Poisson; g(r)<1 ⇒ inhibition/repulsion at scale r; g(r)>1 ⇒ clustering at scale r). Different r can show *both* short-range repulsion (finite object size / excluded volume) and longer-range clustering in the same dataset — a single omnibus statistic can hide this.
- **relrisk**-type analysis estimates the spatially-varying *conditional probability* of a class label (e.g. P(this cell is Tumor | there is a cell here)) — a distinct question from estimating raw intensity/density of that class.
- The convex hull (or a tissue mask, or a density-based region) — not just the raw bounding rectangle of the coordinates — should define the spatial domain (window) used for intensity/K/G/pcf estimation; the choice affects edge correction and is an analyst decision, not automatic.

## Common mistakes / pitfalls
- **Using a single global threshold when the background is spatially non-uniform** (uneven illumination, vignetting, stray signal from nearby bright objects, batch-to-batch staining differences within one slide). This is the single most common segmentation error — check for it before trusting any global cutoff (including Otsu).
- **Using adaptive/local thresholding when it isn't needed or when the local window is misconfigured.** If the local window is smaller than or comparable to the objects, the "local background" estimate is contaminated by the objects themselves, and thresholding fails. If the window is too large, it fails to track real illumination gradients.
- **Treating segmented-object counts and per-object intensities/areas as measured without error.** Segmentation is itself a noisy estimation step (thresholding + morphology + connected-components + splitting), and its errors (merged objects, holes, spurious fragments) propagate silently into every downstream number — cell counts, per-cell mean intensity, density estimates — with no automatic accounting of that added uncertainty. Any downstream test/effect-size should be understood as conditional on a fixed, imperfect segmentation, not as if it were a direct measurement.
- **Skipping ground-truth validation of automated segmentation.** It is genuinely hard to get a gold standard, but that is a reason to obtain at least a modest manually-annotated subset for validation — not a reason to skip validation altogether.
- **Not inspecting the segmentation trade-off.** Raising a threshold/offset reduces false merges of touching objects but increases holes/fragmentation inside objects; lowering it does the reverse. There is no parameter setting that removes both error types — you must visualize the actual result (overlay labels on the source image) at the chosen setting, for more than one image.
- **Conflating pixel-level and object-level (cell-level) statistics.** A histogram/summary computed over all raw pixels in an image answers a different question than the same summary computed over per-object means — a large or bright object contributes proportionally more raw pixels than a small one, biasing pixel-pooled statistics relative to a "one cell = one data point" analysis. Decide, and state, which unit of analysis a claim is about.
- **Naive independence-assumption tests on neighboring pixels or neighboring cells.** Adjacent pixels are correlated by construction (smoothing, PSF blur, shared illumination) and neighboring cells are frequently spatially correlated (shared microenvironment, physical adjacency, batch/tile effects) — plugging such values into a test that assumes i.i.d. observations (plain t-test across pixels, or across cells without accounting for spatial clustering/design) inflates apparent significance.
- **Ignoring edge effects in any spatial-point-process statistic.** Density/K/G/L/pcf estimates computed without an edge correction are systematically biased (typically too low) near the boundary of the observation window — compare corrected vs. uncorrected estimates, or at minimum know which one your software returns by default.
- **Missing or excluded image tiles masquerading as spatial "exclusion."** Suspiciously empty rectangular regions in a spatial scatter of segmented cells are a classic sign of a missing/failed acquisition tile, not real biological exclusion — always check the raw image/scan for acquisition gaps before interpreting sparse regions as biology.
- **Reading short-range repulsion as "no clustering."** Cells have finite size and cannot overlap, so G/K/L/pcf will show repulsion at very short distances even in genuinely clustering populations — examine the full curve across distance scales, not a single summary distance.
- **Confusing intensity/density estimation with conditional class-probability estimation.** "Are there more points here" (density) and "given a point here, how likely is it class X" (relrisk-style) are different analyses and need different estimators; don't substitute one for the other.
- **Batch effects across imaging sessions/staining rounds** (illumination, staining efficiency, scanner settings) behave like batch effects in any other high-throughput assay — require the same experimental-design precautions (blocking, normalization, don't confound batch with biological condition) as in genomics.
- **Lossy compression (JPEG) on images destined for quantification.** Any image used for downstream measurement should be stored/read in a lossless format (PNG, TIFF); JPEG artifacts alter pixel intensities in ways that corrupt quantitative feature extraction.
- **Axis/coordinate-system mismatches.** Image-native coordinates (origin top-left, y increases downward) vs. Cartesian/plotting coordinates (origin bottom-left, y increases upward) can silently flip spatial relationships (e.g. up/down, above/below tissue landmarks) if not tracked consistently through a pipeline.
- **Treating correlated per-object features as independent inputs.** Per-cell intensity features from overlapping masks/channels (e.g. mean nuclear DAPI, mean actin in nucleus, mean actin in cell body) are typically strongly correlated; naive downstream multivariate analysis (PCA, clustering) should account for this, and apparent "outlier" cells in such analyses are often segmentation artifacts rather than a real subpopulation — check the underlying image before biological interpretation.
- **Using an arbitrary numeric threshold rule (e.g. "mode + 6 widths") without acknowledging it's ad hoc.** Such rules can work well in practice but should be validated on the actual data (does the histogram really show two components there?), not applied blindly across batches/channels with different noise properties.

## Assumptions to verify
- Stationarity/homogeneity of the point process (λ(p) ≈ const) before using the plain (homogeneous) Poisson null, K, or G function — if intensity clearly varies spatially (e.g. across tissue architecture), use the inhomogeneous variants (`Kinhom`, `relrisk`-aware estimators) instead.
- Independence of counts in non-overlapping regions (the core Poisson-process assumption) — verify there isn't a known biological or technical mechanism (cell signaling, shared tile, shared illumination) that would induce correlation across regions.
- The adaptive-thresholding assumption that each local window is background-dominated (objects sparse relative to window size) — check object density vs. window size.
- The mixture-model assumption behind a fitted background/foreground threshold (e.g. log-normal background + flat, largely non-overlapping foreground) — confirm by looking at the actual (log-)intensity histogram, don't assume it holds for a new channel/dataset.
- The spatial domain/window used for intensity or K/G/pcf estimation (bounding box vs. convex hull vs. tissue mask) — an arbitrary or too-generous window biases edge-corrected estimates and point densities.
- One-to-one correspondence between a connected component and a true biological object — verify merged/split objects aren't systematically present, especially in dense or touching-cell regions.
- Pixel-to-metric spatial calibration — before interpreting any distance-based statistic (nearest-neighbor distance, K-function range) in physical units, confirm the pixel size conversion factor used is correct and consistent across the imaging batch.
- Whether the reported intensity values are on a physically meaningful/comparable scale across images (same acquisition settings, same normalization) before comparing intensities between conditions or batches.

## Diagnostic checks
- Always visually overlay the segmentation (labeled objects, colored masks) on the original image before trusting any downstream number — do this for several representative images/regions, not just one.
- Plot/tabulate the size (pixel area) distribution of segmented objects to catch merged objects (anomalously large) and fragments/noise (anomalously small); use this to set a plausible size-filter range instead of trusting every connected component.
- Inspect the (log) pixel-intensity histogram for the assumed bimodal/mixture shape before applying a mixture-model or fixed-multiplier threshold rule; overlay the fitted location/threshold on the histogram to sanity check placement.
- Run a sensitivity analysis: vary the threshold offset, adaptive-window size, and morphological structuring-element size, and check how much object counts and per-object summary statistics move — fragile results (large swings from small parameter changes) are a red flag, not a reason to just pick the "nicest-looking" setting.
- Compare edge-corrected vs. non-edge-corrected intensity/K/G/pcf estimates; large divergence (typically near the window boundary) flags edge bias that must be corrected for, not ignored.
- Plot the empirical G/K/L/pcf curve against its theoretical homogeneous-Poisson counterpart across the full range of distances r, and note the r at which they cross (scale of transition from repulsion to attraction), rather than reducing spatial dependence to a single number.
- Scan spatial scatterplots of segmented objects for suspiciously empty or overly regular rectangular regions (tile/acquisition artifacts) before attributing sparsity to biology.
- Check the raw dynamic range (min/max, histogram) of a newly loaded image before processing — catches unrescaled low-bit-depth data, saturation, or unexpected inversion.
- Look at pairwise scatterplots/correlation of per-object features derived from overlapping masks/channels to understand collinearity before feeding them into PCA/clustering, and inspect any "outlier" cells in feature space against the original image to rule out segmentation artifacts.

## Quick checklist

- [ ] Visually inspected segmentation overlays on real images (multiple images/regions), not just accepted the pipeline output?
- [ ] Validated automated segmentation against at least some manually-annotated ground truth?
- [ ] Ran a sensitivity/robustness check on threshold, window-size, and morphological parameters?
- [ ] Are downstream counts/intensities/areas being treated as having zero measurement error, when they actually depend on an imperfect segmentation step?
- [ ] Confirmed whether the analysis question is about pixel-level or object(cell)-level statistics, and used the matching unit of analysis?
- [ ] Checked for spatial autocorrelation among cells/pixels before applying an independence-assuming test?
- [ ] Applied edge correction for any density/K/G/pcf spatial statistic, and checked it against the uncorrected version?
- [ ] Ruled out missing/failed acquisition tiles as the explanation for any apparent spatial "exclusion" pattern?
- [ ] Verified the pixel-to-metric spatial calibration before interpreting any distance-based statistic in physical units?
- [ ] Considered batch effects across imaging/staining sessions and whether the design confounds batch with biological condition?
- [ ] Confirmed images used for quantification were stored/read losslessly (not JPEG)?
- [ ] Checked collinearity among per-object features derived from overlapping channels/masks, and treated "outlier" objects as candidate segmentation artifacts before biological interpretation?

## Key terms
- **Global threshold**: one intensity cutoff for an entire image (e.g. Otsu, `img > c`). Fails under spatially varying background.
- **Adaptive/local threshold**: cutoff computed per-region from a local background estimate (e.g. local mean/median filter), then subtracted before applying an offset cutoff.
- **Morphological operations**: `erode`/`dilate`/`open`/`fillHull` — binary-mask cleanup operations, not linear filters.
- **Connected-component labeling**: assigns a unique integer label to each connected foreground region — the pixel→object transition (`scipy.ndimage.label`, `skimage.measure.label`).
- **Voronoi tessellation / seeded propagation**: partitions space (or a mask) among seed objects by nearest-seed assignment; used to split touching objects and grow nuclear seeds into full cell segmentations.
- **Feature extraction**: computing per-object intensity/shape/texture descriptors (`skimage.measure.regionprops`) from a segmentation + intensity image.
- **Marked point process**: a set of spatial locations each carrying an attribute/label (e.g. cell centroid + cell type).
- **Homogeneous Poisson process**: null model of complete spatial randomness — constant intensity λ, independent non-overlapping-region counts.
- **Intensity λ(p)**: local expected point density of a spatial process; estimated via edge-corrected kernel density.
- **Edge correction**: adjustment for the undercounting of neighbors near a spatial window's boundary.
- **G-function**: CDF of nearest-neighbor distance; compared against the Poisson theoretical curve to detect clustering/repulsion.
- **Ripley's K / L-function**: second-moment measures of expected neighbor counts vs. distance r; L is the variance-stabilized, easier-to-plot version (`L(r)=r` under Poisson).
- **Pair correlation function g(r)**: derivative-based local density-vs-distance measure; g(r)=1 Poisson, <1 repulsion, >1 clustering, evaluated per distance scale r.
- **Relative risk (relrisk)**: spatially-varying conditional probability of a class label, distinct from raw intensity.
- **Convex hull / tissue mask (window)**: the spatial domain used to define "inside" the point process for edge correction and intensity normalization — an analyst choice that affects all downstream spatial statistics.
